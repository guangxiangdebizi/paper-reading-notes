## 一、集合预测损失（§3.1）

### 原文 1（问题定义：固定大小集合，一次解码）

> *"DETR infers a fixed-size set of N predictions, in a single pass through the decoder, where N is set to be significantly larger than the typical number of objects in an image. One of the main difficulties of training is to score predicted objects (class, position, size) with respect to the ground truth. Our loss produces an optimal bipartite matching between predicted and ground truth objects, and then optimize object-specific (bounding box) losses."*

**直译：** DETR 在通过解码器的**单次前向**中推断出一个**固定大小为 N** 的预测集合，其中 N 被设定为显著大于图像中目标的典型数量。训练的主要困难之一是如何相对于真值来给预测的目标（类别、位置、尺寸）打分。我们的损失在预测目标与真值目标之间产生一个**最优二分图匹配**，然后优化逐目标的（边界框）损失。

**解读：** 这一段定下损失设计的三步逻辑：
1. **固定 N 且远大于实际目标数**——COCO 平均每图 7 个目标，DETR 取 N=100，多出来的槽位必须学会说"我这里没目标"；
2. **训练的核心难题是"打分"**：集合预测没有天然的对应关系（不像分类任务第 i 个输出对第 i 个标签），谁对应谁必须先解出来；
3. 解法分两步——**先匹配、后算损失**。匹配把"无序集合"问题转化为"一对一配对"问题，配对完成后就可以按对算标准的分类 + 框回归损失。N=100 而 COCO 平均每图仅 7 个目标，意味着绝大多数槽位必须学会输出"无目标"。

### 原文 2（公式 (1)：最优匹配的数学表述）

> *"Let us denote by y the ground truth set of objects, and ŷ = {ŷᵢ}ᴺᵢ₌₁ the set of N predictions. Assuming N is larger than the number of objects in the image, we consider y also as a set of size N padded with ∅ (no object). To find a bipartite matching between these two sets we search for a permutation of N elements σ ∈ S_N with the lowest cost:*
>
> *σ̂ = arg min_{σ∈S_N} Σᵢ L_match(yᵢ, ŷ_{σ(i)})   (1)*
>
> *where L_match(yᵢ, ŷ_{σ(i)}) is a pair-wise matching cost between ground truth yᵢ and a prediction with index σ(i). This optimal assignment is computed efficiently with the Hungarian algorithm, following prior work (e.g. [43])."*

**直译：** 记 y 为目标的真值集合，ŷ = {ŷᵢ}ᴺᵢ₌₁ 为 N 个预测的集合。假设 N 大于图像中目标的数量，我们把 y 也视为大小为 N 的集合——用 ∅（无目标）补齐到这个大小。为在这两个集合之间找到二分图匹配，我们搜索 N 个元素的一个**置换** σ ∈ S_N 使代价最低：

$$\hat{\sigma} = \arg\min_{\sigma \in S_N} \sum_i L_{\text{match}}(y_i, \hat{y}_{\sigma(i)}) \tag{1}$$

其中 L_match(yᵢ, ŷ_{σ(i)}) 是真值 yᵢ 与下标为 σ(i) 的预测之间的**成对匹配代价**。这个最优指派由**匈牙利算法**高效算出，沿袭了前人工作（如 [43]）。

**解读：** 公式 (1) 有三个值得细读的细节：
- **真值集合用 ∅ 补齐到 N**：这样两边大小相等，"匹配"严格成为 N 元置换 σ——数学上干净，且把"无目标"处理成与真实类别并列的一个合法标签，而不是流程外的特例；
- **搜索对象是置换 σ ∈ S_N**：即"哪个预测配哪个真值"的全排列中找总代价最小者。暴力枚举是 N! 种（N=100 时约 10¹⁵⁸），而匈牙利算法把二分图最优指派解到多项式时间（O(N³)），这是该损失可用的前提；
- **匹配只在训练时做**：匈牙利算法是前向之外的"裁判"，只决定损失怎么算，不参与梯度传播，推理时完全不需要它。

### 原文 3（匹配代价的具体构成）

> *"The matching cost takes into account both the class prediction and the similarity of predicted and ground truth boxes. ... For the prediction with index σ(i) we define probability of class cᵢ as p̂_σ(i)(cᵢ) and the predicted box as b̂_σ(i). With these notations we define L_match(yᵢ, ŷ_σ(i)) as -1{cᵢ≠∅} p̂_σ(i)(cᵢ) + 1{cᵢ≠∅} L_box(bᵢ, b̂_σ(i))."*

**直译：** 匹配代价同时考虑类别预测与预测框—真值框的相似度。……对于下标为 σ(i) 的预测，我们把类别 cᵢ 的概率记作 p̂_σ(i)(cᵢ)，预测框记作 b̂_σ(i)。据此定义匹配代价为：

$$L_{\text{match}}(y_i, \hat{y}_{\sigma(i)}) = -\mathbb{1}_{\{c_i \ne \varnothing\}}\, \hat{p}_{\sigma(i)}(c_i) + \mathbb{1}_{\{c_i \ne \varnothing\}}\, L_{\text{box}}(b_i, \hat{b}_{\sigma(i)})$$

**解读：** 匹配代价 = **分类项 + 框项**，由指示函数 1{cᵢ≠∅} 分情况：
- 真值是真实目标（cᵢ ≠ ∅）：代价 = 负的类别概率 + 框距离——"这个预测把该类说得多准、框画得多近"；
- 真值是 ∅（补齐槽位）：代价 = 0，与预测内容无关——即"把某个预测派给 ∅"这件事本身不产生匹配代价。

紧接原文还有一段重要的工程说明：

> *"Notice that the matching cost between an object and ∅ doesn't depend on the prediction, which means that in that case the cost is a constant. In the matching cost we use probabilities p̂_σ(i)(cᵢ) instead of log-probabilities. This makes the class prediction term commensurable to L_box(·, ·) ... and we observed better empirical performances."*

**直译：** 注意目标与 ∅ 之间的匹配代价不依赖预测内容，即此时代价是常数。在匹配代价中我们使用**概率** p̂_σ(i)(cᵢ) 而非对数概率。这使得分类项与 L_box(·,·) **量纲可比**……且我们观察到更好的经验性能。

**解读：** 两个看似琐碎、实则关键的实现决策：
1. **匹配用概率、损失用对数概率**：匹配阶段只是"选最优配对"，不需要梯度，用概率（线性尺度）能与框损失在数值上可比，避免 log 把低概率压到 -∞ 附近扭曲匹配决策；真正反传的损失（公式 (2)）仍回到标准的 -log p。同一套类别输出，在"裁判"与"打分"两个环节用不同变换——值得在复现时严格照抄；
2. **∅ 的匹配代价是常数**：这意味着匹配算法不会"挑"哪个预测去填 ∅（反正代价一样），填谁由真实目标先挑完剩下的决定。

### 原文 4（匹配步骤的历史坐标）

> *"This procedure of finding matching plays the same role as the heuristic assignment rules used to match proposal [37] or anchors [22] to ground truth objects in modern detectors. The main difference is that we need to find one-to-one matching for direct set prediction without duplicates."*

**直译：** 这个寻找匹配的过程，扮演的是现代检测器中把 proposal [37] 或 anchor [22] 指派给真值目标的那些**启发式指派规则**的同一角色。主要区别在于：为了无重复的直接集合预测，我们需要找到**一对一**匹配。

**解读：** 这句是论文少见的"与旧范式逐项对表"时刻，值得单独记一笔：

| | 旧检测器 | DETR |
|---|---|---|
| 训练指派 | 启发式规则（IoU 阈值，如 >0.5 为正、<0.4 为负，中间灰色地带丢弃） | 匈牙利算法求全局最优指派 |
| 指派关系 | **多对一**（多个 anchor 配同一目标）→ 必然产生重复预测 → 需要 NMS 收尾 | **一对一**（一个预测独占一个目标）→ 从源头无重复 |
| 是否可学 | 规则写死，不参与优化 | 匹配准则本身仍是规则，但匹配的代价函数（分类概率 + 框损失）随训练变好 |

一句话：**NMS 在 DETR 里不是被"去掉"了，而是被"前置并升维"了**——去重约束从推理后处理搬进了训练损失（一对一匹配），代价由匈牙利算法在训练时每图计算一次。

### 原文 5（公式 (2)：匈牙利损失）

> *"The second step is to compute the loss function, the Hungarian loss for all pairs matched in the previous step. We define the loss similarly to the losses of common object detectors, i.e. a linear combination of a negative log-likelihood for class prediction and a box loss defined later:*
>
> *L_Hungarian(y, ŷ) = Σᵢ₌₁ᴺ [ -log p̂_σ̂(i)(cᵢ) + 1{cᵢ≠∅} L_box(bᵢ, b̂_σ̂(i)) ]   (2)*
>
> *where σ̂ is the optimal assignment computed in the first step (1). In practice, we down-weight the log-probability term when cᵢ = ∅ by a factor 10 to account for class imbalance. This is analogous to how Faster R-CNN training procedure balances positive/negative proposals by subsampling [37]."*

**直译：** 第二步是计算损失函数，即对前一步匹配出的所有配对计算匈牙利损失。我们仿照常见检测器的损失来定义它：类别预测的负对数似然与后文定义的框损失的线性组合：

$$L_{\text{Hungarian}}(y, \hat{y}) = \sum_{i=1}^{N} \big[ -\log \hat{p}_{\hat{\sigma}(i)}(c_i) + \mathbb{1}_{\{c_i \ne \varnothing\}}\, L_{\text{box}}(b_i, \hat{b}_{\hat{\sigma}(i)}) \big] \tag{2}$$

其中 σ̂ 是第一步 (1) 算出的最优指派。实践中，当 cᵢ = ∅ 时我们把对数概率项**降权 10 倍**以应对类别不平衡，这类似于 Faster R-CNN 训练过程通过子采样平衡正/负 proposal [37]。

**解读：** 对比公式 (1) 与公式 (2)，结构几乎一样，差异恰恰藏着设计用心：
1. **匹配用线性概率，损失用负对数**：(1) 的分类项是 -p̂，(2) 的分类项是 -log p̂。匹配只求排序正确，损失要求对错误预测施加足够大的梯度（log 在 p→0 时趋于无穷，惩罚更狠）；
2. **∅ 槽位也参与损失**：(2) 对全部 N 个槽位求和，被派给 ∅ 的槽位仍有 -log p̂(∅) 项——即"无新闻席位必须学会自信地说没有新闻"。但 N=100 而真实目标平均只有 7 个，∅ 类样本占比约 93%，类别严重不平衡，故对 ∅ 的 log 项**降权 10 倍**；
3. **降权 10 倍的对标**：论文明确类比 Faster R-CNN 的正负样本子采样（正负 1:3 采样）。两种范式处理同一个不平衡问题：旧范式靠**丢弃**多数负样本，DETR 靠**降权**多数 ∅ 样本——都是"减少负样本对梯度的统治"，但 DETR 的方式不丢信息。

### 原文 6（框损失：为什么是 GIoU + ℓ1 的组合）

> *"Unlike many detectors that do box predictions as a Δ w.r.t. some initial guesses, we make box predictions directly. While such approach simplify the implementation it poses an issue with relative scaling of the loss. The most commonly-used ℓ₁ loss will have different scales for small and large boxes even if their relative errors are similar. To mitigate this issue we use a linear combination of the ℓ₁ loss and the generalized IoU loss [38] L_iou(·,·) that is scale-invariant. Overall, our box loss is L_box(bᵢ, b̂_σ(i)) defined as λ_iou L_iou(bᵢ, b̂_σ(i)) + λ_L1 ‖bᵢ − b̂_σ(i)‖₁ where λ_iou, λ_L1 ∈ R are hyperparameters. These two losses are normalized by the number of objects inside the batch."*

**直译：** 与许多把框预测做成相对某个初始猜测的增量 Δ 的检测器不同，我们**直接**做框预测。这种做法虽然简化实现，但带来损失相对尺度的问题：最常用的 ℓ₁ 损失对小框和大框会有不同的尺度，即使它们的相对误差相似。为缓解该问题，我们使用 ℓ₁ 损失与**尺度不变**的广义 IoU 损失 [38] L_iou(·,·) 的线性组合。整体上框损失定义为：

$$L_{\text{box}}(b_i, \hat{b}_{\sigma(i)}) = \lambda_{\text{iou}} L_{\text{iou}}(b_i, \hat{b}_{\sigma(i)}) + \lambda_{L1} \|b_i - \hat{b}_{\sigma(i)}\|_1$$

其中 λ_iou、λ_L1 ∈ R 为超参数。这两项损失按 batch 内目标数量归一化。

**解读：** 三个要点：
1. **直接预测绝对框坐标**（归一化中心 + 宽高），不做相对 anchor 的 Δ 回归——因为没有 anchor 了。框以相对整图的归一化坐标表示（b ∈ [0,1]⁴）；
2. **ℓ₁ 的尺度病**：同样偏移 10 像素，对 30 像素宽的小框是 33% 的相对误差，对 300 像素宽的大框只有 3.3%；但 ℓ₁ 对两者惩罚相同（若用归一化坐标则相反地偏向惩罚大框）。单用 ℓ₁ 会让模型"嫌大框难伺候、偏袒某一端"；
3. **GIoU 负责尺度不变性**：广义 IoU 是相对量（面积比），天然尺度不变。两项互补——ℓ₁ 在框接近时仍有稳定梯度（IoU 在框不交时为 0、GIoU 梯度弱），GIoU 保证相对尺度正确。实验部分（Table 4）会给出消融：λ_L1=5、λ_iou=2，两项缺一不可（单用 ℓ₁ 只有 35.8 AP）。

## 二、架构三件套（§3.2）

### 原文 7（总述：简单到只需几百行）

> *"The overall DETR architecture is surprisingly simple and depicted in Figure 2. It contains three main components, which we describe below: a CNN backbone to extract a compact feature representation, an encoder-decoder transformer, and a simple feed forward network (FFN) that makes the final detection prediction. Unlike many modern detectors, DETR can be implemented in any deep learning framework that provides a common CNN backbone and a transformer architecture implementation with just a few hundred lines. Inference code for DETR can be implemented in less than 50 lines in PyTorch [32]. We hope that the simplicity of our method will attract new researchers to the detection community."*

**直译：** DETR 的整体架构简单得出人意料，见图 2。它包含三个主要组件：用于抽取紧凑特征表示的 **CNN 骨干网**、**编码器-解码器 Transformer**、以及做最终检测预测的简单**前馈网络（FFN）**。与许多现代检测器不同，DETR 可以在任何提供通用 CNN 骨干网与 Transformer 架构实现的深度学习框架中用仅几百行代码实现。DETR 的推理代码可以用不到 **50 行 PyTorch** 实现。我们希望该方法的简单性能为检测社区吸引新研究者。

**解读：** 架构段开篇先立"简单性"人设，并给出可验证的承诺：几百行训练代码、不到 50 行推理代码（附录 A.6 兑现——36 行核心代码，见第 4 站）。最后一句 "attract new researchers" 道出一个社区层面的动机：2020 年前后的目标检测工程门槛极高（anchor 设计、RPN、RoIAlign、NMS 调参），新人入门困难；DETR 把检测器还原成"CNN + 标准 Transformer + 一个 FFN"，等于把门槛降到"会用 PyTorch 的 Transformer"。

### 原文 8（Backbone：从图像到特征图）

> *"Starting from the initial image x_img ∈ R^{3×H₀×W₀} (with 3 color channels), a conventional CNN backbone generates a lower-resolution activation map f ∈ R^{C×H×W}. Typical values we use are C = 2048 and H, W = H₀/32, W₀/32."*

**直译：** 从初始图像 x_img ∈ R^{3×H₀×W₀}（3 个颜色通道）出发，一个常规的 CNN 骨干网生成低分辨率的激活图 f ∈ R^{C×H×W}。我们使用的典型值是 C = 2048，H = H₀/32、W = W₀/32。

**解读：** 骨干网用最普通的 ResNet（取最后一阶段的特征，stride 32）——DETR 的创新完全不在特征提取，而在特征之后发生的事。两个数字值得记住：通道数 C=2048（ResNet-50/101 的 C5 输出），空间下采样 32 倍。800×1333 的输入到这里变成约 25×42 ≈ **1000 个空间位置**的 token 序列——这个数字后面算复杂度（第 4 站）和讨论"encoder 在干嘛"时都会用到。另注（原文脚注 2）：batch 内图像尺寸不一时以 0 填充到 batch 内最大尺寸，注意力机制对填充不敏感。

### 原文 9（Encoder：降维、拉平、全场通气）

> *"First, a 1×1 convolution reduces the channel dimension of the high-level activation map f from C to a smaller dimension d, creating a new feature map z₀ ∈ R^{d×H×W}. The encoder expects a sequence as input, hence we collapse the spatial dimensions of z₀ into one dimension, resulting in a d×HW feature map. Each encoder layer has a standard architecture and consists of a multi-head self-attention module and a feed forward network (FFN). Since the transformer architecture is permutation-invariant, we supplement it with fixed positional encodings [31,3] that are added to the input of each attention layer."*

**直译：** 首先，一个 1×1 卷积把高层激活图 f 的通道维从 C 降到较小的 d，得到新特征图 z₀ ∈ R^{d×H×W}。编码器以序列为输入，因此我们把 z₀ 的空间维度**压平成一维**，得到 d×HW 的特征图。每个编码器层具有标准架构，由多头自注意力模块与前馈网络（FFN）组成。由于 Transformer 架构对**置换不变**，我们用固定的位置编码 [31,3] 补充它，加在每层注意力的输入上。

**解读：** Encoder 前的两步预处理：① 1×1 conv 把 2048 维降到 d=256（省算力）；② 把 H×W 的空间网格**拉平成 HW 长度的序列**——二维图像正式变成 Transformer 认识的"句子"。两个关键点：
- **置换不变 → 必须补位置编码**：自注意力对 token 顺序完全无感（打乱输入，输出也只是对应打乱），若不加位置编码，encoder 看到的就是一袋无序的像素块，"上下左右"概念尽失。DETR 用固定的 2D 正余弦位置编码（附录 C），且**加在每层注意力的输入**而非只加一次——与 ViT 只在输入加一次的做法不同，这点第 4 站附录还会再提；
- Encoder 的职责（后文消融会证明）：约 1000 个空间 token 做全局自注意力，把混在一起的实例线索**先拆分开**——0→6 层 encoder 带来约 4 AP，尤其在大目标上。

### 原文 10（Decoder 与 object queries：并行解码的核心差异）

> *"The decoder follows the standard architecture of the transformer, transforming N embeddings of size d using multi-headed self- and encoder-decoder attention mechanisms. The difference with the original transformer is that our model decodes the N objects in parallel at each decoder layer, while Vaswani et al. [47] use an autoregressive model that predicts the output sequence one element at a time. ... Since the decoder is also permutation-invariant, the N input embeddings must be different to produce different results. These input embeddings are learnt positional encodings that we refer to as object queries, and similarly to the encoder, we add them to the input of each attention layer. The N object queries are transformed into an output embedding by the decoder. They are then independently decoded into box coordinates and class labels by a feed forward network (described in the next subsection), resulting N final predictions. Using self- and encoder-decoder attention over these embeddings, the model globally reasons about all objects together using pair-wise relations between them, while being able to use the whole image as context."*

**直译：** 解码器遵循 Transformer 的标准架构，使用多头自注意力与编码器-解码器注意力机制变换 N 个大小为 d 的嵌入。与原始 Transformer 的区别在于：我们的模型在每层解码器上**并行解码 N 个目标**，而 Vaswani 等人 [47] 使用一次预测输出序列一个元素的自回归模型。……由于解码器同样对置换不变，N 个输入嵌入**必须互不相同**才能产生不同的结果。这些输入嵌入是**可学习的位置编码**，我们称之为 **object queries**；与编码器类似，我们把它们加到每层注意力的输入上。N 个 object queries 被解码器变换成输出嵌入，然后由一个前馈网络（下一小节描述）独立地解码为框坐标与类别标签，得到 N 个最终预测。通过对这些嵌入使用自注意力与编码器-解码器注意力，模型利用目标之间的两两关系**对所有目标做全局联合推理**，同时能够使用整幅图像作为上下文。

**解读：** 这段是全文概念密度最高的一段，拆开四层：
1. **与机器翻译 Transformer 的唯一结构差异：非自回归**。翻译必须一个词一个词吐（下一个词依赖上一个词）；检测的 N 个目标之间没有顺序依赖（集合无序），所以 N 个输出并行算——这是引言"并行解码"主张在架构上的落点。附录指出第一层 decoder 的自注意力甚至可以跳过（输入本来就是独立的可学习嵌入），见图 10；
2. **object queries 的身份界定很特别："learnt positional encodings"（可学习的位置编码）**。这个措辞值得琢磨：encoder 侧的位置编码是**固定**的（告诉 token 你在图里的哪），decoder 侧的 object queries 是**学出来**的——初始是随机向量，训练中演化为"第 i 个槽位该去哪里找目标"的先验。后文槽位特化分析（第 3 站）证实：学完之后，不同 query 确实表现出对图像区域与目标尺寸的不同偏好；
3. **置换不变 → queries 必须互异**：若 N 个 query 相同，置换不变的 decoder 会输出 N 份相同预测（N 个完全一样的框）——多样性只能从输入端注入。这与"可学习位置编码"的称谓自洽：queries 本质是给 N 个槽位各自不同的"初始坐标/身份"；
4. **decoder 内两种注意力的分工**：自注意力 = queries 之间互通有无（谁盯哪个目标，协调去重）；交叉注意力 = 每个 query 通看全部 encoder 输出（从整图找证据）。原文最后一句是对这两者的总结——"pair-wise relations between them"（去重）+ "the whole image as context"（找全）。

### 原文 11（FFN 预测头与 ∅ 类）

> *"The final prediction is computed by a 3-layer perceptron with ReLU activation function and hidden dimension d, and a linear projection layer. The FFN predicts the normalized center coordinates, height and width of the box w.r.t. the input image, and the linear layer predicts the class label using a softmax function. Since we predict a fixed-size set of N bounding boxes, where N is usually much larger than the actual number of objects of interest in an image, an additional special class label ∅ is used to represent that no object is detected within a slot. This class plays a similar role to the 'background' class in the standard object detection approaches."*

**直译：** 最终预测由一个带 ReLU 激活、隐藏维度为 d 的**三层感知机**加一个线性投影层计算。FFN 预测相对输入图像的归一化框中心坐标、高度与宽度，线性层用 softmax 预测类别标签。由于我们预测固定大小为 N 的边界框集合，而 N 通常远大于图像中感兴趣目标的实际数量，我们使用一个额外的特殊类别标签 **∅** 表示槽位内未检测到目标。该类别扮演标准检测方法中"**背景**"类的类似角色。

**解读：** 预测头的设计要点：
- **3 层感知机（隐藏维 d=256）+ 线性层**：比"单层线性头"更重。消融（第 3 站 Table 3）证明 FFN 去掉一层就掉 2.3 AP——从 decoder 嵌入到"类别 + 框"的最后映射并非线性可分，需要非线性深度；
- **框输出**：归一化的 (cx, cy, h, w) 四个数，直接对应损失里的 b ∈ [0,1]⁴；
- **∅ 类与"背景类"的对位**：旧检测器的"背景"是负样本 anchor/proposal 的标签，DETR 的 ∅ 是**槽位级**标签——不是"这个区域没东西"，而是"我这个预测席位今天没认领到目标"。论文明确点名这一对位关系，便于老读者建立直觉。

### 原文 12（辅助解码损失：缓解收敛慢的关键补丁）

> *"We found helpful to use auxiliary losses [1] in decoder during training, especially to help the model output the correct number of objects of each class. We add prediction FFNs and Hungarian loss after each decoder layer. All predictions FFNs share their parameters. We use an additional shared layer-norm to normalize the input to the prediction FFNs from different decoder layers."*

**直译：** 我们发现在解码器中使用辅助损失 [1] 有帮助，尤其有助于模型输出每个类别正确数量的目标。我们在**每个解码器层之后**都加上预测 FFN 与匈牙利损失。所有预测 FFN **共享参数**。我们使用一个额外的**共享 layer-norm** 来归一化来自不同解码器层的、进入预测 FFN 的输入。

**解读：** 这是针对 DETR 收敛慢（500 epoch）的工程补丁，机制如下：
- **每层 decoder 后都接一份完整损失**（各自先过匈牙利匹配再算匈牙利损失）：标准 Transformer 只在最后一层出损失，深层监督把"输出正确数量的目标"这一信号直接注入到每一层，等价于给 6 层 decoder 每层都装了独立的绩效考核；
- **FFN 参数共享 + 额外共享 layer-norm**：6 层的 decoder 输出分布各不相同（浅层粗、深层精），若直接喂给同一个 FFN 会互相干扰；加一层共享 layer-norm 先把各层输出各自归一化到可比分布，再进共享 FFN——"归一化"与"映射"分离，前者按层归一、后者全层共享；
- 原文点明辅助损失的特殊功效是"help the model output the correct number of objects of each class"——即治"数量不对"这个集合预测特有的病：漏检、多检都是集合大小错误，深层监督直接压这个错误。
