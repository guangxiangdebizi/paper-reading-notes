## 〇、问题定义与总管线

**原文（问题定义）：**
> *"Given a pair of consecutive RGB images, I1, I2, we estimate a dense displacement field (f1, f2) which maps each pixel (u,v) in I1 to its corresponding coordinates (u′,v′) = (u+f1(u), v+f2(v)) in I2."*

给相邻两帧，输出两张和图像同尺寸的"位移图"。三个阶段，**全部可微、端到端**：

```
I1, I2 ∈ R^(H×W×3)
  │
  │ ① 特征提取（只跑一次）
  │    特征编码器 g_θ：两帧都用 → 特征图 ∈ R^(H/8×W/8×256)
  │    上下文编码器 h_θ：只用 I1 → 上下文特征（同形状）
  ▼
  │ ② 计算视觉相似（只算一次）
  │    4D 相关体 C ∈ R^(H×W×H×W)（1/8 分辨率下的 H,W）
  │    → 池化成 4 层金字塔 {C1,C2,C3,C4}
  ▼
  │ ③ 迭代更新（跑 N 次，N≈24~32）
  │    f0 = 0
  │    循环：用当前流 f_k 去金字塔查表 → ConvGRU 更新 → f_{k+1} = f_k + Δf
  ▼
最终流场，凸组合上采样回全分辨率
```

## 一、§3.1 特征提取：为什么有两个编码器？

**原文：**
> *"The feature encoder network is applied to both I1 and I2 and maps the input images to dense feature maps at a lower resolution. Our encoder outputs features at 1/8 resolution ... where we set D = 256. The feature encoder consists of 6 residual blocks, 2 at 1/2 resolution, 2 at 1/4 resolution, and 2 at 1/8 resolution."*

**拆解：** 特征编码器把两帧各自变成 **1/8 分辨率、256 维**的特征图。结构很朴素：6 个残差块，逐级下采样（½→¼→⅛）。

**原文（第二个编码器）：**
> *"We additionally use a context network. The context network extracts features **only from the first input image I1**. ... Together, the feature network g_θ and the context network h_θ form the first stage of our approach, which only need to be performed once."*

**🔑 为什么上下文编码器只看 I1？**

因为光流是**有方向的任务**——估计的是"I1 里的东西跑到 I2 哪里去了"。I1 是"出发点"，I2 是"目的地"：
- **特征编码器**管"匹配"：两帧都要，用来算"谁像谁"
- **上下文编码器**管"先验"：只需要出发点。它编码"这个场景里大概会有什么运动"——比如"这是马路，车大概率往前开"、"这是天空，基本不动"

**这正是"learning to optimize"对照表的第二行**：传统方法里手工设计的"运动平滑先验"，在 RAFT 里就是这个从数据中学出来的 context 网络。

两个编码器都只跑一次，后面迭代不再碰它们。

## 二、§3.2 视觉相似：4D 相关体与金字塔（全文最漂亮的设计）

### 1. 全配对相关体

**原文：**
> *"the correlation volume is formed by taking the dot product between all pairs of feature vectors. ... C ∈ R^(H×W×H×W), C_ijkl = Σ_h g_θ(I1)_ijh · g_θ(I2)_klh"*

**拆解：** I1 的**每个**像素的特征，和 I2 的**每个**像素的特征做内积：

```
C[i, j, k, l] = ⟨ I1在(i,j)处的特征,  I2在(k,l)处的特征 ⟩

含义："I1 的像素 (i,j) 和 I2 的像素 (k,l) 有多像"
```

维度 H×W×H×W（1/8 分辨率下）。实现上就是**一次大矩阵乘法**——GPU 最爱，这就是"All-Pairs"名字的由来。

**对比传统方法：** 经典匹配只在"当前猜测附近的小窗口"里算相似度，窗口外一无所知；RAFT 一上来把**所有可能性**全算出来存好，后面想查哪查哪——"把证据全部摆上桌"。

### 2. 相关金字塔：替代 coarse-to-fine 的关键 ⭐

**原文：**
> *"We construct a 4-layer pyramid {C1, C2, C3, C4} by pooling the last two dimensions of the correlation volume with kernel sizes 1, 2, 4, and 8. Thus, volume C_k has dimensions H×W×H/2^k×W/2^k."*

**拆解：** 对 4D 相关体做平均池化，**只池化后两个维度（I2 那一侧）**：

| 层级 | 池化核 | 尺寸 | 覆盖的位移范围（原图尺度） |
|---|---|---|---|
| C1 | 1 | H×W×H×W | 小位移（精细） |
| C2 | 2 | H×W×H/2×W/2 | |
| C3 | 4 | H×W×H/4×W/4 | |
| C4 | 8 | H×W×H/8×W/8 | **大位移（粗犷）** |

**为什么这个设计能取代图像金字塔？** coarse-to-fine 的两大死穴：

- **死穴 1：大位移在高分辨率找不到** → 金字塔把**查询范围**（后两维）逐级池化放大，C4 层一个像素代表原图 64×64 的区域，大位移照样有证据；
- **死穴 2：小快物体在低分辨率消失** → 金字塔**前两维（I1 侧）永远不池化**，查询点始终是全分辨率的——小物体不会被"粗化"掉。

> **一句话：图像金字塔是"把题目变简单"，相关金字塔是"把答案库分层索引"——题目（I1 的每个像素）始终原样保留。**

### 3. 查表算子（Lookup）

**原文：**
> *"Given a current estimate of optical flow (f1, f2), we map each pixel x = (u,v) in I1 to its estimated correspondence in I2: x′ = (u+f1(u), v+f2(v)). We then define a local grid N(x′)_r = {x′+dx | dx ∈ Z², ||dx||₁ ≤ r} ... Since N(x′)_r is a grid of real numbers, we use bilinear sampling."*

**拆解：** 每一轮迭代，每个像素干这件事：

```
1. 我当前猜：I1的(u,v) 对应 I2 的 x' = (u+f1, v+f2)
2. 以 x' 为中心，取 L1 距离 ≤ r 的一圈邻居（默认 r=4）
3. 去相关金字塔里把这圈邻居的"相似度值"双线性采样出来
4. 四层金字塔都查一遍，拼接成一张"证据特征图"
```

**原文（半径设计的妙处）：**
> *"A constant radius across levels means larger context at lower levels: for the lowest level, k=4 using a radius of 4 corresponds to a range of **256 pixels** at the original resolution."*

四层用**同一个半径 r=4**，但因为低层被池化过 8 倍，同样的半径在 C4 层实际覆盖原图 **256 像素**的范围。一次 lookup，像素同时拿到"256 像素尺度的大方向证据"和"32 像素尺度的精确定位证据"。

### 4. 效率：O(N²) 其实不是问题

**原文：**
> *"The all pairs correlation scales O(N²) ... but only needs to be computed once and is constant in the number of iterations M. However, there exists an equivalent implementation ... which scales O(NM) exploiting the linearity of the inner product and average pooling."*

**拆解：**
- 4D 相关体**只算一次**，迭代 M 次不再重算，实际开销 O(N² + NM)；
- 还有个等价的懒计算版本 O(NM)：不预存相关体，改存池化后的特征图，查表时**按需现算**内积；
- 实测：预计算版在 GPU 上快得很（高度优化的矩阵乘法），1088×1920 的视频也只占推理时间 17%。先用简单版，真成瓶颈再换。

## 三、§3.3 迭代更新：ConvGRU 与不动点

### 1. 更新框架

**原文：**
> *"Our update operator estimates a sequence of flow estimates {f1, ..., fN} from an initial starting point f0 = 0. With each iteration, it produces an update direction Δf which is applied to the current estimate."*

即 `f_{k+1} = f_k + Δf_k`。两个设计意图（原文明说）：
> *"we used tied weights across depth and use **bounded activations** to encourage convergence to a fixed point"*

**权重共享 + 有界激活（tanh）= 鼓励收敛到不动点**。"循环"不是堆层数的技巧，是**在模拟一个收敛的优化过程**。

**初始化**：默认全零流场；处理视频序列时用 **warm-start**——把上一对帧的流前向投影过来当起点（遮挡空洞用最近邻填）。这是"单一分辨率流场"的白送福利：coarse-to-fine 架构想做这种跨帧热启动很别扭。

### 2. 三路输入

**原文：**
> *"the correlation features are then processed by 2 convolutional layers. Additionally, we apply 2 convolutional layers to the flow estimate itself. Finally, we directly inject the input from the context network."*

每轮迭代，更新器吃三样东西拼起来：

```
x_t = [ 相关特征(查表结果, 过2层conv) ;
        流特征(当前流 f_k, 过2层conv) ;
        上下文特征(context 网络直出) ]
```

对应优化算法三要素：**当前证据**（相关）、**当前解**（流）、**问题先验**（上下文）。

### 3. ConvGRU（Eq. 3-6）

标准 GRU，把全连接层全换成 3×3 卷积：

```
z_t = σ(Conv3x3([h_{t-1}, x_t], W_z))          # 更新门
r_t = σ(Conv3x3([h_{t-1}, x_t], W_r))          # 重置门
h̃_t = tanh(Conv3x3([r_t ⊙ h_{t-1}, x_t], W_h)) # 候选状态（tanh 有界！）
h_t = (1−z_t) ⊙ h_{t-1} + z_t ⊙ h̃_t            # 新状态
```

**为什么是 GRU 而不是普通卷积？** 消融答案：门控机制让流估计序列**更容易收敛**（更新门可以选择"这一轮少改点"）。轻量变体 separable ConvGRU：3×3 拆成 1×5 和 5×1 两个 GRU，扩大感受野不加多少参数。

### 4. 输出与上采样

**原文：**
> *"The hidden state outputted by the GRU is passed through two convolutional layers to predict the flow update Δf. The output flow is at 1/8 resolution."*

全网络都在 1/8 分辨率上迭代，最后一步才上采样。

**上采样不是简单的双线性**：

> *"We upsample the optical flow to full resolution by taking the full resolution flow at each pixel to be the convex combination of a 3x3 grid of its coarse resolution neighbors. We ... predict a H/8×W/8×(8×8×9) mask and perform softmax over the weights of the 9 neighbors."*

**拆解：** 网络为每个粗分辨率像素**学习一组 9 个邻居的混合权重**（softmax 归一化，凸组合），把 1/8 的流"涂抹"成全分辨率。好处：**运动边界处可以学会偏向某一侧**，不像双线性插值那样把遮挡边界糊成一片。

## 四、§3.4 监督：序列损失

**原文（Eq. 7）：**
> *"L = Σ_i γ^(N−i) · ||f_gt − f_i||₁, where we set γ = 0.8"*

**拆解：** **每一轮**的中间预测 f_i 都算损失（L1 距离），权重 γ^(N−i) 指数递增——越接近最后一轮权重越大。

**为什么监督所有中间步？** ① 梯度直接打到每个迭代步，不用穿过整条循环链，训练稳定；② 逼着**每一轮更新都是"朝正确答案走"**。这和 GRU 的收敛设计配套。

### 附：与"方法"强相关的实现细节（实验节）

- **梯度截断技巧**：`f_{k+1} = f_k + Δf` 反向传播时，**只让梯度走 Δf 分支，把 f_k 分支的梯度清零**（学自 FlowNet2）——避免梯度穿过所有展开的迭代步，省显存又稳。
- **迭代次数是自由超参**：训练 12 次，Sintel 评测 32 次、KITTI 24 次——推理加迭代就能涨点，权重共享架构独享的福利。

## 🧠 小结

| 组件 | 数学形式 | 设计意图（对照传统优化） |
|---|---|---|
| 特征编码器 g_θ | 6 残差块 → ⅛ 分辨率、256 维 | 学出来的"匹配代价"（数据项） |
| 上下文编码器 h_θ | 同结构，只吃 I1 | 学出来的"运动先验"（正则项） |
| 4D 相关体 + 金字塔 | C_ijkl = 全配对内积；只池化后两维 | 全证据库；**替代图像金字塔**：查询点恒高分辨率（抓小物体）+ 索引分层（抓大位移） |
| Lookup | L1 半径 4 邻域双线性采样，四层拼接 | 每轮迭代重看原始证据；低层同半径=覆盖原图 256 像素 |
| ConvGRU 更新 | 门控+tanh 有界+权重共享 | 学出来的"下降方向"；收敛到不动点 |
| 凸组合上采样 | 学习 9 邻居 softmax 权重 | 保住运动边界 |
| 序列损失 | Σ γ^(N−i)‖f_gt−f_i‖₁, γ=0.8 | 每步都朝正确答案 |

**三个必须带走的结论：**
1. **相关金字塔是 RAFT 的灵魂**：不池化 I1 侧保住小物体，池化 I2 侧覆盖大位移——一个结构同时解掉 coarse-to-fine 的两大死穴。
2. 整个网络是**"优化算法的可微翻译"**：特征=数据项、context=正则项、GRU 迭代=下降步、监督每步=保证下降方向正确。
3. 迭代次数、初始化（零/warm-start）都成了**自由旋钮**——权重共享架构的红利。
